# Article voice

Write for a person trying to decide what to do next.
Lead with the answer, then the common case and one concrete example.
Put prerequisites beside the step they change. Move uncommon cases later.

- Separate a notification, crawling, and indexing. HTTP 200 proves only what its endpoint reports.
- Use eligible job or livestream URLs in Indexing API examples. Never imply ordinary pages become supported through a wrapper.
- Teach the reader how to interpret a result, including what it cannot establish.
- Prefer a small working example over a production framework. Label execution limits.
- Keep API reference details in the relevant guide. Link when the next question needs a different article.
- Compare mechanisms and current plans fairly. Avoid winner tables based on missing evidence.
- Mention Request Indexing only when inspected implementation helps the reader's task. Do not claim live integration tests from code inspection.
- Do not invent personal experience, indexing speed, success rates, Google detection signals, or measured search demand.
- Keep publication dates. Update review dates only for articles actually revised and reviewed.

## Writing passes

Run factual review first. Then run both humanize-writing passes.
Remove filler, repeated takeaways, unnecessary FAQs, stock comparisons, and forced promotional endings.
Vary rhythm while preserving a clear sequence. Do not add digressions to sound human.
Record surface and structural changes in the brief. Recheck scope, dates, examples, and qualifications afterward.
